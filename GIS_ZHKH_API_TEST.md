# ГИС ЖКХ: тест регистрации через API АСУД

Это отдельная экспериментальная сборка. API backend включается только пресетом
`gis-api-test`; обычные пресеты ОЭК, ТЭС, ГИС ЖКХ и СБИС продолжают работать как
раньше. По умолчанию API выключен, режим — `dry-run`, изменения запрещены.

Не заменяйте этой сборкой рабочий экземпляр до успешных `dry-run` и `probe`.
Распакуйте её в отдельную папку вместе с `asud_gis_api_test.bat`.

## Режимы BAT

Запустите `asud_gis_api_test.bat` двойным щелчком и выберите режим либо передайте
его первым аргументом:

```bat
asud_gis_api_test.bat dry-run
asud_gis_api_test.bat probe
asud_gis_api_test.bat live-one
```

- `dry-run` — разбирает и валидирует максимум одно письмо локально. HTTP не
  отправляется, документ в АСУД не создаётся. Требуется подтверждённый
  `branch_id`, потому что из него и номера обращения вычисляется стабильный
  внешний GUID.
- `probe` — выполняет только запрос проверки/поиска. Создание, вложение и
  регистрация запрещены.
- `live-one` — создаёт и регистрирует максимум один реальный документ. Перед
  запуском BAT требует вручную ввести `LIVE-ONE`.

Ограничение в один документ задаётся независимо от настроек. Удаление исходного
MSG после теста отключено.

## Настройка без секретов

Скопируйте `settings.json.example` в `settings.json` рядом с `asud.exe`. В секции
`asud_api` оставлены пустыми все значения, которые нельзя угадывать. Получите их
у владельца API АСУД и внесите без изменения названий полей:

- `base_url` и точные `endpoints.find_objects2`, `find_appointment`,
  `handle_object`, `get_object`, `execute_action`;
- `lis`, `user`, `branch_id` и `branch_name`;
- `incoming_type_path`, `addressee_id` и проверяемое `addressee_name`;
- подтверждённые владельцем API `delivery_type`, `branch_attribute`,
  `author_id` и `author_attribute`, а также необходимые `incoming_attributes`.

Перед созданием карточки программа отдельным read-only запросом проверяет, что
`addressee_id` действительно относится к единственной активной должности
указанного `addressee_name` в заданном филиале. Несовпадение блокирует
регистрацию до первого изменяющего запроса.

Отдельно получите письменное подтверждение, что API принимает вложения `.msg`,
и точный допустимый размер. Только после этого можно выставить
`attachment.confirm_msg_supported=true` и положительное ограничение
`attachment.max_bytes`. Значения `false` и `0` блокируют `live-one`; BAT их не
переопределяет.

Относительный endpoint допустим только вместе с заполненным `base_url`.
Не копируйте URL из браузерной карточки АСУД: это не обязательно адрес API.
`registration_action` оставлен равным `registration` по справочнику API;
перед `live-one` подтвердите это значение у владельца API. Тестовая версия не
отправляет документ на резолюцию, поэтому `resolution_action` пустой.

В preset `gis-api-test` проверьте `folder`: это должна быть только папка выгрузки
ГИС ЖКХ. Поля `asud_api.enabled=false`, `asud_api.mode=dry-run`,
`allow_mutations=false` и `asud_api_enabled=false` — намеренные предохранители;
BAT выставляет временные разрешения согласно выбранному режиму.

## Авторизация — только через переменные среды

Логин, пароль, bearer-токен и пользовательский заголовок запрещено хранить в
`settings.json`, BAT, исходниках или отправлять в Git. Поддерживаемый тип задаёт
`ASUD_API_AUTH_TYPE`: `none`, `basic`, `bearer` или `custom`.

Для выбранного типа задайте только необходимые переменные в окружении процесса:

- basic: `ASUD_API_BASIC_USERNAME`, `ASUD_API_BASIC_PASSWORD`;
- bearer: `ASUD_API_BEARER_TOKEN`;
- custom: `ASUD_API_AUTH_HEADER_NAME`, `ASUD_API_AUTH_HEADER_VALUE`.

Не присылайте содержимое этих переменных вместе с логом. Если задаёте их через
обычный `cmd`, учитывайте, что значение существует в окружении этого окна и его
дочерних процессов. После теста закройте окно.

## Порядок безопасной проверки

1. Положите в тестовую папку один небоевой MSG ГИС ЖКХ и запустите `dry-run`.
   До запуска заполните подтверждённый `branch_id`; endpoint'ы и авторизация
   этому режиму не нужны.
2. Убедитесь по логу, что распознаны корреспондент, тема, дата и вложение, а
   итоговый статус сообщает об отсутствии HTTP/изменений.
3. Для `probe` заполните `user`, филиал, адресата и endpoint'ы
   `find_objects2`/`find_appointment` (и `base_url`, если endpoint'ы
   относительные), затем задайте переменные авторизации.
4. Проверьте успешный ответ чтения, TLS и отсутствие созданного документа.
5. Для `live-one` заполните остальные подтверждённые endpoint'ы/ID, подтвердите
   формат/лимит вложения в секции `attachment`, оставьте в папке ровно одно
   согласованное письмо, повторно проверьте адресата и введите подтверждение в
   BAT.
6. Сразу найдите созданную карточку в АСУД, сверьте реквизиты и вложение.

Так как `resolution_action` намеренно пустой, успешный `live-one` завершится
защитным статусом `REGISTERED_ONLY`: карточка зарегистрирована, но на резолюцию
не отправлена. Это ожидаемый результат этой тестовой версии; MSG и terminal
marker остаются для ручной сверки, автоматический повтор запрещён. Строка в
реестр резолюций при `REGISTERED_ONLY` не создаётся, поэтому daemon Халецкой
этот документ не увидит и не обработает.

Чтобы позднее получить финальный статус `OK`, нужно отдельно согласовать
отправку на резолюцию и только после этого явно задать подтверждённое действие
`resolution_action` (по справочнику ожидается `send_on_resolution`). Это уже
другой тестовый сценарий и не входит в текущий режим «только регистрация».

Восемь исключённых тематик ГИС ЖКХ (2.1, 2.2, 2.3, 2.16, 2.25, 5.1, 5.2 и 23)
по-прежнему не должны доходить до регистрации.

## Важные ограничения

- Поддержка вложения `.msg` самим API пока не считается подтверждённой. Не
  запускайте `live-one`, пока владелец API не подтвердит формат и максимальный
  размер. Предохранители `confirm_msg_supported=false` и `max_bytes=0`
  намеренно делают live-запуск невозможным.
- Не отключайте `verify_tls`. Для корпоративного центра сертификации установите
  корректную доверенную цепочку в Windows вместо обхода проверки TLS.
- После сетевого таймаута нельзя просто повторять `live-one`: сначала проверьте,
  не появилась ли карточка в АСУД. Иначе возможен дубль.
- Рядом с MSG создаются служебные файлы `<имя>.asud_api.claim` и
  `<имя>.asud_api_state.json`. Claim защищает от параллельной обработки, state
  сохраняет фазу и внешний GUID. При неоднозначном результате не удаляйте их до
  ручной проверки карточки.
- Никогда не подставляйте неподтверждённые endpoint'ы, ID или имена атрибутов:
  программа должна остановиться на неполной конфигурации.

Переменные `ASUD_API_*` могут временно переопределять одноимённые поля секции
`asud_api`. Полный перечень поддерживаемых override'ов виден в
`settings.json.example`; для штатного запуска достаточно редактировать JSON,
оставляя секреты только в env.
