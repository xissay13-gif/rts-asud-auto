# Ответы начальников отделов

Отдельная программа `asud_reports.exe` предназначена только для прикрепления
ответов. `Прикрепление_отчетов.bat` запускает обработку папки с готовыми
ответами. Папку можно перетащить на BAT либо указать в `settings.json` рядом
с `asud_reports.exe`. Нужен совместимый `msedgedriver.exe` рядом с программой.
При первом запуске скопируйте `settings.json.example` в `settings.json`
и укажите папку с ответами. При обновлении сохраните свой `settings.json`
и журнал `.asud_replies.json` в папке ответов.

Батник запускает Edge в фоне (`--headless`), без окна браузера.
При обновлении EXE после ошибки заполнения отчёта сохраните журнал обработки:
ошибка до нажатия «Сохранить отчет» допускает повторную попытку при запуске.

## Подготовка папки

Пока рабочего образца имени нет, используется явное правило:

- `41359__Ответ.pdf` — короткий номер входящего документа.
- `41359__Ответ.msg` — письмо Outlook, прикрепляемое целиком.
- `ОРТС_8_41359__Ответ.pdf` — полный номер `ОРТС/8/41359`.
- `ОРТС_8_41359__Приложение.pdf` — дополнительное вложение того же отчёта.

Допустимы также `41359.pdf` и `ОРТС_8_41359.pdf`. Название после двойного
подчёркивания произвольное. Файлы одного номера группируются в один отчёт.
Полный номер предпочтителен. Короткий принимается только при единственном
совпадении среди поручений на исполнение. Несколько подходящих поручений
останавливают обработку. Не смешивайте короткий и полный номер в одной партии.

Обрабатываются файлы непосредственно в выбранной папке; подпапки не обходятся.
Поддерживаются PDF, DOC/DOCX, RTF, TXT, XLS/XLSX, JPG/JPEG, PNG, TIFF, ZIP, MSG.
Ограничения размера и форматов на стороне АСУД сохраняются.
Программа не извлекает номер из содержимого ответа и не угадывает его по адресу
или фамилии. Нераспознанные имена и пустые файлы выводятся в журнал.
Подготовьте все вложения одного документа до запуска. При мониторинге переносите
готовую группу одновременно; недавно изменённые файлы ждут следующего прохода.

## Настройки

Раздел настроек в `settings.json`:

```json
"reply_reports": {
  "folder": "D:\\Ответы",
  "switch_to_user": "",
  "report_text": "Ответ прикреплен.",
  "poll_interval_sec": 300,
  "upload_timeout_sec": 90,
  "file_stable_seconds": 5
}
```

Пустая `switch_to_user` оставляет текущую учётную запись. Для замещения
можно указать имя нужной доступной учётки. Обработка
привязана к её внутреннему логину, а не к фамилии отправителя резолюции.

В `report_text` задаётся единый текст отчёта, до 2000 символов. Например,
`Отправлен ответ потребителю.` используйте, если ответ уже отправлен потребителю.

Разовый запуск: `asud_reports.exe --folder "D:\Ответы"`.
Мониторинг: `asud_reports.exe --folder "D:\Ответы" --watch`.
Для фонового браузера добавьте `--headless`. Остановка — Ctrl+C.

## Путь в АСУД и проверка результата

Программа открывает «Полученные задания → Исполнение», очищает ограничение
даты получения, ищет точный номер и открывает само поручение. В «Жизненном
цикле» выбирает строку текущего исполнителя, её меню «Добавить отчет»,
заполняет текст, загружает файлы и ждёт появления их имён в списке вложений.
Затем один раз нажимает «Сохранить отчет» и повторно открывает карточку,
проверяя текст и вложения у того же исполнителя.

Кнопка «Завершить» не нажимается. Отправка письма потребителю в этот режим
не входит. Исходные файлы остаются в папке.

В `.asud_replies.json` сохраняются учётка, номер и SHA-256 файлов:

- `saved` — сохранение проверено; неизменённая партия пропускается.
- `pending` — сохранение могло произойти, но проверка не завершена.
  Сначала проверьте отчёт в АСУД; автоматического повторного прикрепления нет.
- `failed` — ошибка до попытки сохранения; повторный запуск может повторить работу.

Изменённая или дополненная ранее сохранённая партия требует проверки;
существующий отчёт автоматически не перезаписывается. Не удаляйте журнал
для обычного повторного запуска. Если `pending` проверен вручную и отчёт
точно отсутствует, при остановленной программе можно изменить только статус
соответствующей записи на `failed`. Это разрешит следующую попытку.
Одновременная обработка одной папки заблокирована. Используйте постоянную
папку для ответов каждого отдела, чтобы сохранялся журнал повторов.

Реализация построена по пяти переданным снимкам DOM. Среди них нет состояния
после загрузки вложения и после сохранения отчёта. Проверку этих состояний
нужно подтвердить на рабочей АСУД; при отсутствии ожидаемых признаков программа
останавливается и не отмечает документ как успешно обработанный.
